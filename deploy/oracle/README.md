# Oracle VPS deployment: SwapnoPay payment receipts

This stack hosts the provider-owned API at `api.swapnopay.top`. Merchant payment
verification remains in each merchant's Supabase database. The Oracle service
only accepts a constrained `PAYMENT_PAID` receipt event from an enrolled merchant
project and sends fixed transactional messages through the official Google
Workspace mailbox.

## 1. Prepare Oracle Cloud

- Create an Ubuntu 24.04 LTS compute instance with a reserved public IPv4.
- In the OCI Network Security Group allow inbound TCP `22` from an administrator
  IP only, and TCP `80`/`443` from the internet. Do not expose PostgreSQL `5432`.
- Enable automatic security updates, install Docker Engine plus the Compose
  plugin, and keep SSH password authentication disabled.
- Create an `A` record: `api.swapnopay.top -> <reserved Oracle public IPv4>`.
  Caddy obtains and renews the TLS certificate after DNS resolves.

## 2. Configure Google Workspace

Create `payments@swapnopay.top`, enable Gmail API in a Google Cloud project, and
authorize only `https://www.googleapis.com/auth/gmail.send` with offline access.
Store its OAuth client ID, client secret, and refresh token only in the Oracle
host `.env`. Never put these values in Android, Cloudflare Worker variables, or
a merchant-owned Supabase project.

For a Google Workspace organization, keep the OAuth consent app internal and
authorize the `payments@swapnopay.top` mailbox itself. The configured From address
must be that mailbox or a verified Gmail “Send mail as” identity. Treat refresh
tokens as revocable credentials and alert on OAuth refresh failures.

Publish Google Workspace SPF, DKIM, and DMARC records for `swapnopay.top`. Begin
DMARC with monitoring (`p=none`) and review aggregate reports before moving to
`quarantine` or `reject`.

Recommended initial DNS records (use your DNS provider's required trailing-dot
format, and use the DKIM value generated by Google Admin):

| Type | Host | Priority | Value |
| --- | --- | ---: | --- |
| A | `api` | — | Oracle reserved public IPv4 |
| MX | `@` | 1 | `smtp.google.com` |
| TXT | `@` | — | `v=spf1 include:_spf.google.com ~all` |
| TXT | `google._domainkey` | — | Google Admin generated `v=DKIM1; ...` value |
| TXT | `_dmarc` | — | `v=DMARC1; p=none; rua=mailto:dmarc@swapnopay.top` |

Do not publish a second SPF TXT record; merge every authorized sender into one
SPF policy. Wait for SPF/DKIM to pass before enforcing DMARC.

## 3. Start the service

Copy this directory and `gateway-service/` to a restricted directory on the VPS.
Create `.env` from `.env.example`, use independent random values, then run:

```bash
docker compose build --pull
docker compose up -d
curl --fail https://api.swapnopay.top/healthz
```

Back up the `gateway_postgres` volume encrypted and monitor container health,
HTTP 429/5xx responses, Gmail OAuth failures, disk usage, and TLS expiry.

## 4. Enroll one merchant project

Run inside the gateway container (the API key prints once):

```bash
docker compose exec gateway npm run register-merchant -- PROJECT_REF MERCHANT_UUID
```

Set the returned key and webhook secrets in that merchant's Supabase project:

```bash
supabase secrets set \
  PAYMENT_RECEIPT_WEBHOOK_SECRET=RANDOM_DATABASE_WEBHOOK_SECRET \
  SWAPNOPAY_RECEIPT_SERVICE_URL=https://api.swapnopay.top \
  SWAPNOPAY_RECEIPT_API_KEY=THE_ONE_TIME_RETURNED_KEY
supabase functions deploy payment-receipt --no-verify-jwt
```

Create an `INSERT` Database Webhook on `payment_receipt_outbox` targeting
`https://PROJECT_REF.supabase.co/functions/v1/payment-receipt`; add the header
`x-webhook-secret: RANDOM_DATABASE_WEBHOOK_SECRET`. Also schedule the same POST
every minute so failed outbox events are retried. A retry never changes payment
state and is idempotent by `(project_ref,event_id)`.

## Production gate

Rotate any credential ever committed to source control before deployment. Test
with a real low-value payment, confirm merchant DB `orders.status='PAID'`, outbox
`status='SENT'`, Gmail message IDs in the provider DB, and SPF/DKIM/DMARC `pass`
in the received message headers.
